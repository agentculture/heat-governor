## What we measured (2026-11-08/09, read-only unless noted)

- **VENTUNO Q (cultureos):**
  - Detection: `compatible` = `arduino,monza qcom,monaco-monza qcom,qcs8300`.
  - Trip types: all SoC trips are passive. The only critical trips are on the PMIC zones (125 °C). `cpuss-0-0` has an active 38 °C fan trip.
  - The `emc2305` fan is driven by the kernel (cooling_device7).
  - GPU: Adreno devfreq at 479–877 MHz. Board power from `ina232`, 13–17 W idle.
  - Memory temperature: DDR zones `ddrss-0/1`.
  - Baseline: `docs/evidence/2026-11-08-ventunoq-baseline.md`.
- **Memory temperature elsewhere:**
  - Jetson Thor and Orin: none without root. EMC temperature is in BPMP debugfs; `tegrastats` and `nvidia-smi` report none, and Orin's `nvidia-smi` shows a bogus `0`.
  - GB10: none (`nvidia-smi` N/A).
- **Fan ownership:** Jetsons run `nvfancontrol`. The Sparks' ACPI "Fan" devices are firmware-driven.
- **SSH transport:** 0.59 s for a fresh fetch, 0.07 s reused through ControlMaster.
- **History from records:** about 1.0 s for 24 h and 1.3 s for 7 d per box, under `nice -n 19`. 7d buckets are sampled maxima (about every 14th line).
- **Heat:** the Sparks and Thor ran warm, hot and critical during the run.
  - spark peaked at 92.8 °C live.
  - spark2 spent 64% of the week above warm and 21% critical.
  - Thor's 7-day peak was 101 °C.

## What is live

The fleet runs under `core`, the operator's EliteMini (x86, `generic`). It is the one fleet reader.

**core (fleet reader):**

- Install: `uv tool install --reinstall .` in a checkout of the branch (a snapshot). Reinstall from PyPI once 0.16.0 is published.
- `config.toml`: `generic`, `apply = false`, `listen = "127.0.0.1:9476"`, `gpu_clock = false`.
  - Its only thermal zone is ACPI `acpitz`, which reads a constant 20 °C. Its row on the page is a placeholder, not a CPU temperature.
- `fleet.toml`: core `local`; cultureos (ssh alias `arduino`), spark, spark2, thor and orin over `ssh`; `poll_s = 3`.
- User units: `heat-governor.service` (the dry-run daemon) and `heat-governor-mesh.service`.
  - The mesh unit runs `mesh serve --listen 100.95.106.3:9480`, the tailnet address only (the operator's choice). The page is at `http://core:9480` from any tailnet device. It is not on the LAN, and 9476 stays on loopback.
  - Local `mesh status` needs `--url http://100.95.106.3:9480`, or it falls back to a direct read.
- Redeploy after a code change: reinstall, then `systemctl --user restart heat-governor-mesh`.

**cultureos:**

- The daemon still runs (`heat-governor.service`): `ventunoq`, `apply = false`, `listen = "127.0.0.1:9476"`, the two lobes containers as `serving`. core reads it over SSH.
- Its `heat-governor-mesh.service` (the first live site) was disabled and stopped on 2026-11-09, once the core site was confirmed working. The unit file is kept.

**Remote boxes** were upgraded to 0.16.0 from PyPI on 2026-11-10, one at a time (orin, thor, spark2, spark), with the operator's go-ahead. Each box's own config was checked with the new version before its restart, and the root GPU helper was unchanged. Their daemons still run on loopback with `apply = true`. The Spark pair re-formed after each restart.
